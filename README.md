# Прогнозирование потребительского спроса

> Курсовой проект: **«Проектирование и разработка программного средства прогнозирования потребительского спроса на основе нейросетевых моделей»**

Программная система предназначена для загрузки и обработки истории продаж, построения прогноза спроса с помощью нейросетевой модели и отображения полученных результатов пользователю.

## Архитектура

Проект разрабатывается как **monorepo** и включает три отдельных приложения и базу данных:

```text
┌──────────────┐      REST API      ┌──────────────────┐
│   Frontend   │ ─────────────────▶ │     Backend      │
│ React + Vite │ ◀───────────────── │   Spring Boot    │
└──────────────┘                    └────────┬─────────┘
                                           │
                              ┌────────────┴────────────┐
                              │                         │
                              ▼                         ▼
                    ┌─────────────────┐       ┌─────────────────┐
                    │   PostgreSQL    │       │   ML Service    │
                    │  хранение данных│       │ FastAPI/PyTorch │
                    └─────────────────┘       └─────────────────┘
```

- **Frontend** — пользовательский интерфейс, формы, таблицы и графики.
- **Backend** — авторизация, бизнес-логика, проверка данных и координация компонентов.
- **ML Service** — подготовка данных, обучение модели, прогнозирование и расчет метрик.
- **PostgreSQL** — хранение пользователей, товаров, продаж и результатов прогнозирования.

## Основные возможности

- регистрация и авторизация пользователей;
- загрузка исторических данных о продажах;
- проверка, просмотр и фильтрация загруженных данных;
- выбор товара и горизонта прогнозирования;
- обучение и запуск нейросетевой модели;
- сохранение прогнозов и метрик качества;
- отображение фактического и прогнозируемого спроса на графике;
- экспорт результатов;
- журналирование операций и обработка ошибок.

Функциональность будет уточняться и дополняться по мере разработки.

## Требования

Для локальной разработки потребуются:

- Git;
- JDK, совместимый с выбранной версией Spring Boot;
- Maven либо Maven Wrapper из проекта;
- Node.js и выбранный для frontend менеджер пакетов;
- Python и виртуальное окружение;
- PostgreSQL.

Секреты и параметры локального окружения должны храниться в `.env`-файлах или переменных окружения. В Git добавляются только безопасные шаблоны `.env.example`.

## Запуск

> Ниже приведен предварительный шаблон. Команды и пути будут уточнены после создания компонентов.

### 1. База данных

Создать локальную базу PostgreSQL и указать параметры подключения в переменных окружения. Схема будет применяться миграциями из `database/` или средствами backend.

### 2. Backend

Windows:

```powershell
cd backend
.\mvnw.cmd spring-boot:run
```

Linux и macOS:

```bash
cd backend
./mvnw spring-boot:run
```

### 3. ML Service

```powershell
cd ml-service
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Путь к модулю FastAPI будет скорректирован после утверждения структуры ML-сервиса.

### 4. Frontend

```powershell
cd frontend
npm install
npm run dev
```

Перед запуском каждого компонента необходимо создать локальную конфигурацию на основе соответствующего `.env.example`.

## Работа с Git

Используется следующая схема ветвления:

| Ветка | Назначение |
|---|---|
| `main` | стабильное состояние проекта |
| `develop` | объединение готовых задач текущего этапа |
| `feature/<название>` | разработка новой функции |
| `fix/<название>` | исправление ошибки |
| `docs/<название>` | изменение документации |

Рабочий процесс:

1. Обновить `develop` и создать от нее тематическую ветку.
2. Выполнить одну логически завершенную задачу.
3. Проверить сборку, тесты и отсутствие секретов.
4. Сделать коммит с понятным описанием изменения.
5. После проверки объединить ветку с `develop`.

Зависимости, результаты сборки, виртуальные окружения, секреты, приватные датасеты, обученные модели и дампы БД в репозиторий не добавляются. Для необходимых крупных файлов следует использовать внешнее хранилище или Git LFS.
