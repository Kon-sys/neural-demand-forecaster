# Модель данных программного средства

## 1. Назначение документа

Настоящий документ определяет логическую модель данных программного средства прогнозирования потребительского спроса.

Модель данных формируется на основании функциональных требований, пользовательских сценариев и ранее определённой архитектуры системы.

Документ не фиксирует конкретную СУБД и описывает данные на логическом уровне.

## 2. Основные сущности

Для работы программного средства необходимо хранить следующие основные сущности:

1. Dataset — загруженный набор исторических данных.
2. Product — объект прогнозирования.
3. Forecast — запуск прогнозирования.
4. ForecastValue — отдельное прогнозируемое значение.
5. ActualValue — фактическое значение спроса.
6. ForecastMetrics — метрики качества прогноза.
7. ModelVersion — информация об используемой модели.

## 3. Dataset

Сущность `Dataset` представляет зарегистрированный набор исходных данных.

Основные атрибуты:

| Поле | Назначение |
| --- | --- |
| id | Уникальный идентификатор набора данных |
| fileName | Имя исходного файла |
| uploadedAt | Дата и время загрузки |
| rowCount | Количество записей |
| dateFrom | Начало временного диапазона |
| dateTo | Конец временного диапазона |
| validationStatus | Результат проверки данных |
| preprocessingVersion | Версия алгоритма подготовки данных |
| checksum | Контрольная сумма файла или содержимого |

Поле `checksum` может использоваться для идентификации версии исходного набора данных и повышения воспроизводимости результатов.

## 4. Product

Сущность `Product` представляет товар или другой объект, для которого выполняется прогнозирование.

Основные атрибуты:

| Поле | Назначение |
| --- | --- |
| id | Внутренний идентификатор |
| externalId | Идентификатор объекта во входном наборе |
| name | Наименование |
| category | Категория при наличии |
| datasetId | Набор данных, из которого получен объект |

В зависимости от структуры выбранного датасета набор полей может быть расширен.

## 5. Forecast

Сущность `Forecast` представляет отдельный запуск прогнозирования.

Основные атрибуты:

| Поле | Назначение |
| --- | --- |
| id | Уникальный идентификатор запуска |
| datasetId | Использованный набор данных |
| productId | Объект прогнозирования |
| modelVersionId | Использованная версия модели |
| forecastHorizon | Горизонт прогнозирования |
| createdAt | Дата и время запуска |
| status | Состояние выполнения |
| startedAt | Время начала вычисления |
| completedAt | Время завершения |
| errorMessage | Описание ошибки при неуспешном выполнении |

Возможные значения `status`:

- `PENDING`;
- `PROCESSING`;
- `COMPLETED`;
- `FAILED`.

## 6. ForecastValue

Сущность `ForecastValue` хранит отдельное прогнозируемое значение.

Основные атрибуты:

| Поле | Назначение |
| --- | --- |
| id | Уникальный идентификатор |
| forecastId | Связанный запуск |
| date | Дата или временной момент |
| value | Прогнозируемое значение |

Один `Forecast` содержит множество `ForecastValue`.

## 7. ActualValue

Сущность `ActualValue` представляет фактическое значение спроса.

Основные атрибуты:

| Поле | Назначение |
| --- | --- |
| id | Уникальный идентификатор |
| datasetId | Связанный набор данных |
| productId | Объект прогнозирования |
| date | Дата |
| value | Фактическое значение |

Фактические значения используются для сравнения с прогнозом и расчёта метрик качества.

## 8. ForecastMetrics

Сущность `ForecastMetrics` хранит рассчитанные показатели качества.

Основные атрибуты:

| Поле | Назначение |
| --- | --- |
| id | Уникальный идентификатор |
| forecastId | Связанный прогноз |
| mae | Средняя абсолютная ошибка |
| rmse | Среднеквадратичная ошибка |
| mape | Средняя абсолютная процентная ошибка |
| calculatedAt | Дата расчёта |

Метрики могут отсутствовать сразу после формирования прогноза, если для прогнозируемого периода ещё нет фактических значений.

## 9. ModelVersion

Сущность `ModelVersion` описывает версию модели прогнозирования.

Основные атрибуты:

| Поле | Назначение |
| --- | --- |
| id | Уникальный идентификатор |
| modelName | Наименование модели |
| version | Версия |
| createdAt | Дата создания |
| status | Состояние модели |
| metadata | Дополнительные сведения |

В `metadata` могут храниться:

- используемая архитектура;
- версия preprocessing;
- набор основных параметров;
- идентификатор обучающего эксперимента;
- путь или идентификатор артефакта модели.

## 10. Связи сущностей

Основные связи:

    Dataset 1 ---- * Product

    Dataset 1 ---- * ActualValue

    Product 1 ---- * ActualValue

    Dataset 1 ---- * Forecast

    Product 1 ---- * Forecast

    ModelVersion 1 ---- * Forecast

    Forecast 1 ---- * ForecastValue

    Forecast 1 ---- 0..1 ForecastMetrics

## 11. Логическая схема

Упрощённо модель может быть представлена следующим образом:

    Dataset
       |
       +--------< Product
       |
       +--------< ActualValue
       |
       +--------< Forecast
                     |
                     +--------< ForecastValue
                     |
                     +-------- ForecastMetrics
                     |
                     v
                ModelVersion

При физической реализации внешние ключи и ограничения должны обеспечивать целостность связанных данных.

## 12. Требования к целостности

Система должна обеспечивать следующие ограничения:

- Forecast не может ссылаться на несуществующий Dataset;
- Forecast не может ссылаться на несуществующий Product;
- Forecast должен содержать идентификатор версии модели;
- ForecastValue должен принадлежать существующему Forecast;
- ForecastMetrics должны принадлежать существующему Forecast;
- прогнозируемая дата не должна отсутствовать;
- числовое прогнозное значение должно иметь корректный формат.

## 13. Удаление данных

Стратегия удаления должна учитывать наличие связанных результатов.

Удаление Dataset, для которого существуют сохранённые прогнозы, не должно приводить к появлению некорректных ссылок.

На этапе физического проектирования должен быть выбран один из подходов:

- запрет удаления используемых данных;
- каскадное удаление;
- логическое удаление.

Для первой версии предпочтительным является запрет удаления данных, используемых сохранёнными прогнозами, либо логическое удаление.

## 14. Воспроизводимость

Для каждого Forecast должны быть однозначно определены:

- исходный Dataset;
- объект прогнозирования;
- версия модели;
- горизонт;
- дата запуска;
- версия preprocessing, если она влияет на результат.

Это позволяет восстановить контекст получения результата даже после изменения модели в будущем.

## 15. Результат

Сформированная логическая модель определяет минимальный набор сущностей и связей, необходимых для реализации загрузки данных, формирования прогнозов, хранения результатов и оценки качества модели.

Конкретная физическая схема базы данных должна формироваться после выбора технологии хранения.
