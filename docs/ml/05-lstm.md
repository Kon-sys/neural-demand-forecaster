# LSTM Model

## 1. Назначение

В рамках KP-23 реализована нейросетевая модель прогнозирования
потребительского спроса на основе LSTM.

LSTM используется как основная интеллектуальная модель проекта и
сравнивается с baseline-моделью Moving Average.

Модель решает задачу одношагового прогнозирования:

`история спроса -> спрос на следующий день`

На этапе KP-23 модель обучается и настраивается только по TRAIN и
VALIDATION.

Финальная TEST-выборка не используется и сохраняется для объективного
сравнения моделей в KP-24.


## 2. Экспериментальный набор данных

Используется финальный набор данных FreshRetailNet-50K.

Для ML-эксперимента выбрано:

- 300 store-product временных рядов;
- 32 товарные категории первого уровня;
- 29 100 processed observations.

Каждый временной ряд идентифицируется как:

`STORE_<store_id>_PRODUCT_<product_id>`

Целевая переменная:

`quantity`

представляет неотрицательную числовую величину спроса.


## 3. Разделение данных

Используется строго хронологическое разделение.

### TRAIN

`2024-03-28 -> 2024-06-11`

Продолжительность:

`76 дней`

### VALIDATION

`2024-06-12 -> 2024-06-25`

Продолжительность:

`14 дней`

### TEST

`2024-06-26 -> 2024-07-02`

Продолжительность:

`7 дней`

TEST не используется:

- при обучении;
- при выборе размера окна;
- при early stopping;
- при выборе checkpoint;
- при оценке validation-метрик.

TEST сохраняется для KP-24.


## 4. Тип модели

Реализована глобальная univariate LSTM.

Глобальная модель означает, что одна нейронная сеть обучается на
временных окнах всех 300 store-product рядов.

Отдельная LSTM для каждого временного ряда не создаётся.

Такой подход позволяет использовать общие закономерности изменения
спроса и увеличивает количество обучающих примеров при относительно
короткой истории каждого отдельного ряда.

Текущая модель использует только:

`quantity`

Дополнительные признаки FreshRetailNet-50K, включая:

- скидки;
- праздники;
- складские остатки;
- температуру;
- влажность;
- категории товара;

не используются в текущей версии модели.

Это позволяет сравнивать LSTM и Moving Average в сопоставимых условиях:
обе модели используют только исторические значения спроса.


## 5. Формирование временных окон

Для преобразования временного ряда в supervised learning используются
окна следующего вида:

`[y(t-N), ..., y(t-1)] -> y(t)`

где:

- `N` — размер входного окна;
- вход содержит только прошлые наблюдения;
- `y(t)` является прогнозируемым значением.

Будущее значение не включается во входные признаки.


## 6. Основной размер окна

Основная LSTM-конфигурация использует:

`window_size = 14`

Таким образом, для каждого прогноза модель получает две недели
предшествующей истории спроса.

При длине TRAIN 76 дней количество обучающих примеров составляет:

`300 × (76 - 14) = 18 600`

Количество validation targets:

`300 × 14 = 4 200`


## 7. Нормализация

Для LSTM используется Min-Max scaling.

В отличие от общего preprocessing pipeline, для LSTM применяется
отдельный scaler для каждого временного ряда.

Для каждого `product_sku`:

1. определяется minimum только на TRAIN;
2. определяется maximum только на TRAIN;
3. создаётся индивидуальный MinMaxScaler;
4. TRAIN преобразуется этим scaler;
5. VALIDATION преобразуется тем же TRAIN scaler;
6. TEST в дальнейшем также должен использовать только этот TRAIN scaler.

VALIDATION и TEST не участвуют в определении параметров нормализации.

Таким образом исключается data leakage.


## 8. Значения вне диапазона TRAIN

Если значение VALIDATION находится за пределами диапазона, наблюдаемого
на TRAIN, scaled value может быть:

`< 0`

или:

`> 1`

Это является допустимым поведением.

Значение не ограничивается искусственно диапазоном `[0, 1]`, поскольку
такое ограничение изменяло бы фактическое значение спроса.


## 9. PyTorch Dataset

На основе временных окон формируется PyTorch Dataset.

Форма одного входного образца:

`[window_size, 1]`

Для основной модели:

`[14, 1]`

После формирования batch вход LSTM имеет форму:

`[batch_size, sequence_length, input_size]`

То есть:

`[batch_size, 14, 1]`

Target имеет форму:

`[batch_size, 1]`


## 10. Архитектура LSTM

Зафиксирована следующая архитектура:

| Параметр | Значение |
| --- | ---: |
| input_size | 1 |
| hidden_size | 64 |
| num_layers | 2 |
| dropout | 0.2 |
| output_size | 1 |
| window_size | 14 |

Архитектура:

`Input -> LSTM -> Last Hidden State -> Linear -> Prediction`

Количество обучаемых параметров:

`50 497`


## 11. Обучение

Основные параметры обучения:

| Параметр | Значение |
| --- | ---: |
| Batch size | 128 |
| Learning rate | 0.001 |
| Maximum epochs | 100 |
| Random seed | 42 |
| Early stopping patience | 10 |
| Early stopping min delta | 0.0001 |

Оптимизатор:

`Adam`

Loss function:

`MSELoss`

В процессе обучения также применяется gradient clipping:

`max_norm = 1.0`

что ограничивает чрезмерный рост градиентов при обучении рекуррентной
нейронной сети.


## 12. Перемешивание данных

Исходные временные ряды до формирования окон не перемешиваются.

TRAIN, VALIDATION и TEST формируются строго хронологически.

После формирования независимых обучающих окон TRAIN samples могут
перемешиваться внутри DataLoader.

Это не приводит к утечке будущего значения внутрь конкретного входного
окна, поскольку последовательность внутри каждого sample сохраняется.

VALIDATION DataLoader работает без shuffle.


## 13. Early Stopping

После каждой эпохи рассчитывается validation loss.

Если validation loss улучшается, сохраняется новый лучший checkpoint.

Если улучшение отсутствует в течение:

`10 эпох`

обучение прекращается.

Таким образом:

- уменьшается риск переобучения;
- не требуется заранее выбирать точное число эпох;
- сохраняется модель с лучшим validation result.


## 14. Результат основного обучения

Для конфигурации:

`window_size = 14`

получено:

- TRAIN samples: 18 600;
- VALIDATION samples: 4 200;
- выполнено эпох: 30;
- лучшая эпоха: 20;
- best scaled validation loss: 0.039717;
- early stopping: сработал.

Лучший checkpoint соответствует 20-й эпохе.


## 15. Метрики Validation

После загрузки лучшего checkpoint predictions преобразуются обратно в
исходный масштаб спроса.

Метрики рассчитываются не в нормализованном масштабе, а в исходных
значениях `quantity`.

Получены следующие результаты:

| Метрика | Значение |
| --- | ---: |
| MAE | 0.6964 |
| RMSE | 1.2403 |
| MAPE | 57.2054 % |
| Observations | 4200 |
| MAPE observations | 4123 |

MAPE не рассчитывается для наблюдений, у которых:

`actual = 0`

Всего таких validation observations:

`4200 - 4123 = 77`


## 16. Сохранение исходного Ground Truth

В процессе разработки была дополнительно проверена корректность
восстановления фактических значений после scaling.

Scaled targets передаются в PyTorch Tensor типа `float32`.

Если исходное значение `quantity = 0` сначала нормализовать, затем
преобразовать в `float32`, а после этого выполнить inverse transform,
из-за погрешности представления числа может возникнуть значение порядка:

`1e-8`

вместо точного:

`0.0`

Для MAE и RMSE такая погрешность практически не влияет на результат,
однако для MAPE почти нулевой denominator способен приводить к
аномально большой процентной ошибке.

Поэтому для расчёта метрик:

- prediction восстанавливается через inverse transform;
- ground truth берётся непосредственно из исходного processed dataset;
- фактическое значение не восстанавливается из float32 target tensor.

После исправления количество MAPE observations составляет корректные:

`4123`

что совпадает с количеством ненулевых фактических значений validation
dataset.

## 20. Почему LSTM не обязана превосходить Moving Average

Более сложная нейросетевая модель не гарантирует автоматического
уменьшения ошибки.

Текущий эксперимент имеет ряд особенностей:

- TRAIN содержит только 76 дней истории;
- модель использует только один признак `quantity`;
- временные ряды имеют относительно короткую историю;
- retail demand содержит шум;
- простой Moving Average хорошо учитывает краткосрочную локальную
  динамику;
- дополнительные признаки FreshRetailNet пока не используются.

Поэтому близкое качество Moving Average и LSTM является допустимым
экспериментальным результатом.

Архитектура проекта позволяет в дальнейшем расширить LSTM дополнительными
признаками и увеличить объём обучающей истории.


## 21. Контроль переобучения

Для уменьшения риска переобучения используются:

- отдельная VALIDATION-выборка;
- dropout = 0.2;
- early stopping;
- сохранение только лучшего checkpoint;
- gradient clipping;
- фиксированный random seed;
- ограниченная архитектура;
- отсутствие подбора параметров по TEST.

Train и validation loss сохраняются после каждой эпохи для последующего
анализа.

## 23. Data Leakage

В LSTM pipeline соблюдаются следующие ограничения:

1. выбор временных рядов выполняется на TRAIN;
2. TRAIN расположен раньше VALIDATION;
3. VALIDATION расположена раньше TEST;
4. scaler каждого ряда обучается только на TRAIN;
5. окно модели содержит только значения до target date;
6. VALIDATION используется только для настройки и early stopping;
7. TEST не используется при обучении;
8. TEST не используется при выборе размера окна;
9. TEST не используется при выборе checkpoint;
10. итоговая LSTM-конфигурация фиксируется до KP-24.
