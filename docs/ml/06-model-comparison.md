# Model Comparison

## 1. Назначение

В рамках KP-24 выполняется итоговое сравнение двух ранее зафиксированных
моделей прогнозирования потребительского спроса:

- Moving Average;
- LSTM.

Оценка проводится на общей ранее не использовавшейся TEST-выборке.

До открытия TEST были полностью зафиксированы:

- архитектура LSTM;
- размер окна LSTM;
- checkpoint LSTM;
- параметры нормализации;
- размер окна Moving Average;
- протокол вычисления метрик.

После получения TEST-результатов параметры моделей не изменяются.

Это позволяет использовать TEST как независимую финальную выборку.


## 2. Экспериментальный набор данных

Для сравнения используется FreshRetailNet-50K.

В экспериментальной выборке:

- 300 store-product временных рядов;
- 32 товарные категории первого уровня;
- 29 100 processed observations.

Каждый временной ряд идентифицируется в формате:

`STORE_<store_id>_PRODUCT_<product_id>`


## 3. Train / Validation / Test

Используется строго хронологическое разделение.

### TRAIN

`2024-03-28 -> 2024-06-11`

### VALIDATION

`2024-06-12 -> 2024-06-25`

### TEST

`2024-06-26 -> 2024-07-02`

Продолжительность TEST:

`7 дней`

Количество временных рядов:

`300`

Количество TEST observations:

`300 × 7 = 2100`


## 4. Зафиксированные модели

### Moving Average

Baseline был выбран в KP-22.

Зафиксированная конфигурация:

`window = 7`

Validation metrics:

- MAE = 0.6821;
- RMSE = 1.1869;
- MAPE = 56.1874 %.

### LSTM

LSTM была реализована и зафиксирована в KP-23.

Используется конфигурация:

- window_size = 14;
- input_size = 1;
- hidden_size = 64;
- num_layers = 2;
- dropout = 0.2;
- batch_size = 128;
- learning rate = 0.001;
- optimizer = Adam;
- loss = MSE;
- early stopping patience = 10.

Validation metrics:

- MAE = 0.6964;
- RMSE = 1.2403;
- MAPE = 57.2054 %.


## 5. Протокол TEST-оценки

Для обеих моделей используется одинаковый протокол:

`rolling one-step-ahead backtesting`

Для каждого дня `t` прогноз формируется только на основании данных,
которые хронологически расположены раньше `t`.

Предыдущее фактическое значение уже завершившегося TEST-дня может
использоваться при прогнозировании следующего TEST-дня.

Такой режим соответствует протоколу, который использовался ранее на
VALIDATION.

Данный эксперимент оценивает качество последовательного одношагового
прогнозирования.

Он не является recursive multi-step прогнозом сразу на весь горизонт
из семи дней.


## 6. Метрики

Для сравнения используются:

- MAE;
- RMSE;
- MAPE.

### MAE

Показывает среднее абсолютное отклонение прогноза от фактического
значения.

### RMSE

Сильнее увеличивает вклад больших ошибок и позволяет выявлять модели,
которые допускают существенные отдельные отклонения.

### MAPE

Показывает среднюю относительную процентную ошибку.

MAPE не рассчитывается для наблюдений:

`actual = 0`

поскольку процентная ошибка для нулевого denominator не определена.

## 15. Интерпретация per-series результатов

Per-series анализ показывает, что качество прогнозирования зависит от
характера конкретного временного ряда.

LSTM не имеет универсального преимущества для каждого товара и
магазина.

Для части рядов простая локальная динамика достаточно хорошо
аппроксимируется Moving Average.

Для других рядов LSTM способна лучше использовать более длинный
контекст из 14 предыдущих наблюдений.

На основе только текущего эксперимента нельзя однозначно определить,
какие конкретно свойства временного ряда гарантируют преимущество той
или иной модели.

Для этого потребовался бы отдельный анализ:

- уровня вариативности;
- числа нулевых продаж;
- тренда;
- сезонности;
- частоты резких скачков;
- дополнительных товарных признаков.


## 16. Сравнение VALIDATION и TEST

Интересным результатом является изменение относительного качества
моделей между VALIDATION и TEST.

### VALIDATION

Moving Average:

- MAE = 0.6821;
- RMSE = 1.1869;
- MAPE = 56.1874 %.

LSTM:

- MAE = 0.6964;
- RMSE = 1.2403;
- MAPE = 57.2054 %.

На VALIDATION Moving Average имела меньшую ошибку.

### TEST

Moving Average:

- MAE = 0.7158;
- RMSE = 1.3500;
- MAPE = 48.6489 %.

LSTM:

- MAE = 0.6907;

Выбор модели только по одной validation-выборке не гарантирует
сохранения относительного качества на следующем временном интервале.


## 17. Почему MAPE на TEST ниже, чем на VALIDATION

MAPE зависит не только от абсолютной величины ошибки, но и от масштаба
фактического значения.

TEST MAPE оказался ниже validation MAPE для обеих моделей:

Moving Average:

`56.1874 % -> 48.6489 %`

LSTM:

`57.2054 % -> 48.1644 %`

Это не означает автоматического улучшения моделей.

Например, MAE и RMSE на TEST, наоборот, несколько выше.

Снижение MAPE может быть связано с изменением распределения фактических
значений спроса между временными интервалами.

Поэтому абсолютные и относительные метрики должны рассматриваться
совместно.


## 18. Сильные стороны Moving Average

Moving Average имеет следующие преимущества:

- простая реализация;
- высокая интерпретируемость;
- минимальные вычислительные затраты;
- отсутствие процесса обучения;
- быстрое обновление прогноза при поступлении новых данных;
- устойчивое качество на коротких временных рядах;
- хорошая baseline-точка для сравнения сложных моделей.

Кроме того, Moving Average показывает меньшее значение MAE для 127 из
300 исследуемых рядов.


## 19. Ограничения Moving Average

Основные ограничения:

- использует только фиксированное локальное окно;
- не обучается на закономерностях нескольких временных рядов;
- не может автоматически изучать нелинейные зависимости;
- не использует длинный скрытый контекст;
- не использует дополнительные признаки;
- одинаковый алгоритм применяется ко всем временным рядам.


## 20. Сильные стороны LSTM

LSTM имеет следующие преимущества:

- обучается совместно на данных всех 300 временных рядов;
- способна изучать нелинейные временные зависимости;
- использует более длинный контекст;
- допускает дальнейшее расширение multivariate-признаками;
- может учитывать более сложные паттерны, чем простое среднее.

На TEST LSTM показывает:

- меньшую MAE;
- меньшую RMSE;
- меньшую MAPE;
- меньшую MAE в 173 из 300 временных рядов;
- меньшую дневную MAE в 5 из 7 TEST-дней.


## 21. Ограничения LSTM

Текущая LSTM имеет следующие ограничения:

- требует обучения;
- требует хранения checkpoint и scaler-артефактов;
- сложнее в сопровождении;
- менее интерпретируема;
- имеет более высокие вычислительные затраты;
- использует короткую историю TRAIN;
- использует только один признак `quantity`;
- не использует скидки, складские остатки, погоду или категориальные
  признаки FreshRetailNet.

Кроме того, преимущество LSTM относительно Moving Average на TEST
является умеренным.


## 22. Ограничение текущего протокола

Сравнение выполняется в режиме:

`rolling one-step-ahead`

Это означает, что для следующего дня может использоваться фактическое
значение предыдущего уже завершившегося дня.

Такой протокол подходит для последовательного ежедневного
прогнозирования.

Однако production-сценарий может требовать сформировать прогноз сразу
на несколько будущих дней.

В таком случае фактические значения будущих дней ещё неизвестны, и
потребуется multi-step forecasting.

Один из возможных вариантов:

`recursive forecasting`

при котором прогноз предыдущего шага используется как часть входа для
следующего шага.

Multi-step forecasting должен рассматриваться отдельно от текущей
TEST-оценки.


## 23. Data Leakage

При сравнении соблюдены следующие условия:

1. временные ряды были выбраны только по TRAIN;
2. preprocessing parameters определены только на TRAIN;
3. Moving Average window выбран по VALIDATION;
4. LSTM architecture зафиксирована по VALIDATION;
5. LSTM checkpoint выбран по VALIDATION;
6. TEST не использовался при обучении;
7. TEST не использовался при выборе гиперпараметров;
8. обе модели получили одинаковые TEST observations;
9. параметры не изменялись после открытия TEST.
