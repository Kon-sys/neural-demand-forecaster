# Baseline Model — Moving Average

## 1. Назначение

В качестве базового метода прогнозирования в проекте Demand Forecast
используется скользящее среднее — Moving Average.

Baseline необходим для формирования простой, воспроизводимой и
интерпретируемой точки сравнения, относительно которой далее будет
оцениваться нейросетевая модель LSTM.

Дополнительно используется naive forecast, позволяющий определить,
даёт ли Moving Average преимущество относительно простейшего переноса
последнего известного значения спроса.

## 2. Финальный экспериментальный набор данных

Финальная оценка baseline выполняется на реальном наборе данных
FreshRetailNet-50K.

Исходный набор содержит ежедневные данные розничных продаж для большого
количества комбинаций магазина и товара.

Основными исходными полями для текущей univariate-модели являются:

- `store_id`;
- `product_id`;
- `dt`;
- `sale_amount`.

Поле `sale_amount` используется в качестве целевой величины спроса.

Поскольку `sale_amount` является вещественным числом, ML data contract
допускает неотрицательные числовые значения target, а не только целые
значения количества товара.

## 3. Формирование временного ряда

Один временной ряд определяется комбинацией:

`store_id + product_id`

Во внутреннем формате проекта формируется идентификатор:

`STORE_<store_id>_PRODUCT_<product_id>`

Такой подход не смешивает продажи одного товара в разных магазинах.

Итоговый ML contract:

`product_sku,date,quantity,is_imputed`

где:

- `product_sku` — идентификатор store-product ряда;
- `date` — календарная дата;
- `quantity` — неотрицательная числовая величина спроса;
- `is_imputed` — признак восстановленного календарного наблюдения.

## 4. Выбор временных рядов

Для эксперимента используется 300 store-product временных рядов.

Выбор выполняется исключительно на TRAIN-части исходного набора.

Данные финального EVAL-периода не используются для выбора временных
рядов.

Для повышения разнообразия выборки применяется балансировка по
`first_category_id`.

В выборке представлены 32 категории первого уровня.

Внутри каждой категории временные ряды ранжируются по следующим
критериям:

1. количество дней с ненулевым спросом;
2. суммарная величина продаж на TRAIN;
3. `store_id`;
4. `product_id`.

После ранжирования используется round-robin выбор по категориям.

Это позволяет избежать ситуации, когда итоговая выборка состоит
преимущественно из одной наиболее активной товарной категории.

## 5. Размер итогового набора

Исходный TRAIN-период содержит 90 календарных дней.

Официальный EVAL-период содержит ещё 7 календарных дней.

Для выбранных 300 временных рядов сформировано:

`300 × 97 = 29 100 наблюдений`

Диапазон processed dataset:

`2024-03-28 -> 2024-07-02`

## 6. Train / Validation / Test

Используется строго хронологическое разделение.

### TRAIN

`2024-03-28 -> 2024-06-11`

Продолжительность:

`76 дней`

### VALIDATION

`2024-06-12 -> 2024-06-25`

Продолжительность:

`14 дней`

### TEST

`2024-06-26 -> 2024-07-02`

Продолжительность:

`7 дней`

TEST соответствует EVAL-периоду исходного FreshRetailNet-50K.

Целевые значения TEST не используются для выбора baseline,
гиперпараметров или настройки модели.

Они резервируются для итогового сравнения Moving Average и LSTM.

## 7. Naive Forecast

В качестве дополнительной контрольной модели используется naive
forecast:

`prediction(t) = actual(t - 1)`

То есть прогноз на следующий день равен последнему известному
фактическому значению спроса.

Эта модель используется как простая reference-модель.

## 8. Moving Average

Основной baseline проекта — Moving Average.

При размере окна `N`:

`prediction(t) = mean(y(t-N), ..., y(t-1))`

При прогнозировании значения `y(t)` используются только наблюдения,
которые хронологически предшествуют прогнозируемой дате.

Текущее фактическое значение и будущие наблюдения в расчёте не
используются.

## 9. Исследуемые размеры окна

На одной и той же validation-выборке исследованы:

- 3 дня;
- 7 дней;
- 14 дней;
- 30 дней.

Основным критерием выбора конфигурации заранее определена MAE.

RMSE и MAPE используются как дополнительные показатели.

## 10. Метрики

### MAE

Mean Absolute Error показывает среднее абсолютное отклонение прогнозных
значений от фактических.

### RMSE

Root Mean Squared Error увеличивает вклад больших ошибок и позволяет
лучше оценить наличие значительных отклонений прогноза.

### MAPE

Mean Absolute Percentage Error показывает относительную ошибку в
процентах.

Для наблюдений с:

`actual = 0`

MAPE не рассчитывается, поскольку процентная ошибка содержит деление
на ноль.

## 11. Результаты Validation

Результаты получены на:

`300 × 14 = 4200`

validation-наблюдениях.

| Модель | Окно | Наблюдений | MAE | RMSE | MAPE |
| --- | ---: | ---: | ---: | ---: | ---: |
| Naive | 1 | 4200 | 0.8192 | 1.4610 | 65.0782 % |
| Moving Average | 3 | 4200 | 0.7503 | 1.3267 | 59.4833 % |
| Moving Average | 7 | 4200 | 0.6821 | 1.1869 | 56.1874 % |
| Moving Average | 14 | 4200 | 0.7228 | 1.2616 | 58.5697 % |
| Moving Average | 30 | 4200 | 0.8108 | 1.4389 | 67.7444 % |

Для MAPE использовано 4123 наблюдения.

77 validation-наблюдений имеют фактическое значение спроса, равное
нулю, поэтому они не участвуют в расчёте MAPE.

## 12. Выбор Baseline

Наименьшая MAE получена для:

`Moving Average (window = 7)`

Validation metrics:

- MAE = 0.6821;
- RMSE = 1.1869;
- MAPE = 56.1874 %.

Следовательно, для последующего итогового сравнения фиксируется:

`Moving Average, window = 7`

После фиксации конфигурации размер окна не изменяется на основании
результатов TEST.

## 13. Анализ результатов

Moving Average с окном 7 дней показывает меньшую ошибку по всем
используемым метрикам относительно naive forecast.

Окно 3 дня также улучшает результат относительно naive, однако сильнее
реагирует на краткосрочные изменения спроса.

Увеличение окна с 7 до 14 дней приводит к небольшому ухудшению качества.

При увеличении окна до 30 дней ошибка возрастает ещё сильнее.

Для исследуемых FreshRetailNet временных рядов семидневное окно
обеспечивает лучший баланс между краткосрочной изменчивостью и
сглаживанием спроса.

Дополнительным возможным объяснением результата является недельная
периодичность розничного спроса, однако наличие такой зависимости
должно подтверждаться отдельным анализом и не принимается только на
основании выбранного размера окна.

## 14. Интерпретация MAPE

MAPE имеет значительно большее числовое значение, чем MAE и RMSE.

Это связано с особенностями временных рядов FreshRetailNet.

Значительная часть значений `sale_amount` имеет небольшой абсолютный
масштаб.

При малом фактическом значении даже небольшое абсолютное отклонение
может приводить к большой процентной ошибке.

Поэтому при итоговом сравнении моделей основное внимание уделяется
MAE и RMSE.

MAPE сохраняется как дополнительный относительный показатель.

## 15. Исключение Data Leakage

При проведении baseline-эксперимента выполняются следующие правила:

1. временные ряды выбираются только на основании TRAIN;
2. разделение выполняется исключительно хронологически;
3. случайное перемешивание временных наблюдений не используется;
4. prediction для даты `t` использует только значения до даты `t`;
5. VALIDATION используется для выбора размера окна;
6. TEST не используется для выбора baseline;
7. итоговая конфигурация фиксируется до оценки на TEST.

## 16. Сохранённые артефакты

Baseline experiment формирует локальные файлы:

`validation_predictions.csv`

Содержит фактические и прогнозные значения.

`validation_metrics.csv`

Содержит MAE, RMSE и MAPE для каждой исследованной конфигурации.

`selected_baseline.json`

Содержит выбранную baseline-конфигурацию и validation-метрики.

`summary.txt`

Содержит текстовую сводку эксперимента.

`plots/`

Содержит графики фактических и прогнозируемых значений.

Generated artifacts не добавляются в Git.

## 17. Использование предыдущих наборов данных

Synthetic dataset использовался на ранних этапах разработки для:

- разработки ML pipeline;
- проверки dataset contract;
- автоматизированного тестирования;
- проверки preprocessing;
- первичной проверки baseline.

M5 Forecasting использовался как дополнительная проверка способности
pipeline работать с внешним реальным набором данных.

Финальным экспериментальным набором для дальнейшей разработки модели
является FreshRetailNet-50K.

Метрики synthetic и M5 не используются как итоговые результаты
курсового проекта.

## 18. Итог

В рамках KP-22 реализована baseline-модель прогнозирования
потребительского спроса.

Для финального эксперимента сформирована выборка из 300 реальных
store-product временных рядов FreshRetailNet-50K, включающих 32
товарные категории первого уровня.

Исследованы Moving Average с окнами 3, 7, 14 и 30 дней, а также
naive forecast.

Лучший результат на validation-выборке получен для:

`Moving Average (window = 7)`

Метрики:

- MAE = 0.6821;
- RMSE = 1.1869;
- MAPE = 56.1874 %.

Эта конфигурация фиксируется как baseline проекта.

Финальная TEST-выборка сохраняется для последующего объективного
сравнения Moving Average и LSTM.
