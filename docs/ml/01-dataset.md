# ML Dataset

## Назначение

Датасет используется для построения моделей прогнозирования
потребительского спроса по историческим данным продаж.

Основной временной ряд системы:

`product_sku + date -> quantity`

Каждый товар рассматривается как отдельный ежедневный временной ряд.

## Источник данных

Основным источником данных прикладной системы является таблица `sales`
PostgreSQL.

Связь товара определяется через таблицу `products`:

`products.id -> sales.product_id`

Для ML используется стабильный предметный идентификатор товара `sku`,
а не внутренний идентификатор PostgreSQL.

Raw CSV имеет формат:

`product_sku,date,quantity`

Если достаточная реальная история продаж отсутствует, для разработки,
тестирования и исследовательской части может использоваться
воспроизводимый синтетический датасет.

Синтетические данные должны явно обозначаться как синтетические
и не должны представляться как реальные рыночные наблюдения.

## Raw dataset

Обязательные поля:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `product_sku` | string | идентификатор товара |
| `date` | date | календарная дата |
| `quantity` | integer | количество проданных единиц |

Ограничения:

- `product_sku` не может быть пустым;
- `date` должна быть корректной календарной датой;
- `quantity` должна быть целым числом;
- `quantity >= 0`;
- комбинация `product_sku + date` должна быть уникальной.

Raw dataset хранится локально в `datasets/raw/` и не коммитится в Git.

## Processed dataset

Processed dataset имеет поля:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `product_sku` | string | идентификатор товара |
| `date` | date | календарная дата |
| `quantity` | integer | спрос за день |
| `is_imputed` | boolean | признак восстановленной даты |

Для каждого товара строится непрерывный календарь от первой до последней
наблюдаемой даты этого товара.

Если дата отсутствует внутри наблюдаемого интервала товара, создаётся
строка:

- `quantity = 0`;
- `is_imputed = True`.

Исходные наблюдения получают:

- `is_imputed = False`.

Даты до первого наблюдения товара и после последнего наблюдения товара
искусственно не создаются.

Processed dataset хранится локально в `datasets/processed/`
и не коммитится в Git.

## Проверка качества

Перед использованием processed dataset проверяется:

- наличие обязательных колонок;
- отсутствие null в обязательных полях;
- корректность дат;
- целочисленность `quantity`;
- отсутствие отрицательного спроса;
- отсутствие дубликатов `product_sku + date`;
- хронологический порядок;
- непрерывность ежедневного календаря;
- корректность `is_imputed`;
- нулевое значение `quantity` для восстановленных строк.

## Train / validation / test

Для временных рядов случайное перемешивание не используется.

Разделение выполняется исключительно хронологически:

`TRAIN -> VALIDATION -> TEST`

Train содержит наиболее раннюю часть истории.

Validation следует непосредственно после train и используется для
настройки и выбора модели.

Test содержит наиболее поздний временной интервал и используется только
для итоговой оценки.

Границы разделения задаются явными календарными датами.

Фиксированные проценты и даты не задаются на уровне data pipeline.
Они определяются после анализа фактической длины и качества временных
рядов.

Таким образом исключается попадание будущих наблюдений в данные,
используемые для обучения модели.

Текущая локальная база содержит только тестовые данные:

- 4 наблюдения;
- 1 товар;
- период от 2026-01-01 до 2026-02-01;
- 28 отсутствующих календарных дней внутри периода.

После восстановления календаря получается 32 строки,
из которых 28 являются восстановленными.

Такой набор подходит для проверки data pipeline, но не используется
как полноценный набор данных для обучения и сравнения ML-моделей.
