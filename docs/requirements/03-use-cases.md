# Пользовательские сценарии

## 1. Назначение документа

Настоящий документ определяет основные сценарии взаимодействия пользователя с программным средством прогнозирования потребительского спроса.

Сценарии сформированы на основе процесса TO-BE и функциональных требований системы.

## 2. Основной пользователь

Основным пользователем системы является специалист, которому необходимо получить прогноз потребительского спроса на основании исторических данных и проанализировать результат.

Пользователю не требуется знание внутренней реализации нейросетевой модели.

## 3. UC-01. Загрузка исторических данных

### Цель

Передать системе исторические данные, необходимые для дальнейшего прогнозирования.

### Предусловия

- пользователь открыл программное средство;
- пользователь располагает набором данных допустимого формата.

### Основной сценарий

1. Пользователь переходит к загрузке данных.
2. Пользователь выбирает файл.
3. Система получает файл.
4. Система проверяет его тип и структуру.
5. Система выполняет первичную проверку данных.
6. При успешной проверке набор данных становится доступен для дальнейшей обработки.
7. Система информирует пользователя об успешной загрузке.

### Альтернативный сценарий

Если файл имеет недопустимый формат или содержит критические ошибки:

1. система прекращает обработку;
2. система отображает обнаруженные проблемы;
3. пользователь исправляет исходные данные и повторяет загрузку.

### Результат

В системе доступен проверенный набор исторических данных.

## 4. UC-02. Просмотр информации о наборе данных

### Цель

Проверить основные характеристики загруженных данных перед запуском прогнозирования.

### Предусловия

В систему загружен набор данных.

### Основной сценарий

1. Пользователь выбирает набор данных.
2. Система отображает основные сведения о наборе.
3. Пользователь просматривает доступный временной период и объекты прогнозирования.
4. Пользователь при необходимости переходит к настройке прогноза.

### Результат

Пользователь понимает состав и пригодность выбранного набора данных для дальнейшей работы.

## 5. UC-03. Формирование прогноза

### Цель

Получить прогноз потребительского спроса для выбранного объекта.

### Предусловия

- набор данных успешно загружен;
- данные прошли обязательную проверку;
- в системе доступна рабочая модель прогнозирования.

### Основной сценарий

1. Пользователь открывает форму формирования прогноза.
2. Пользователь выбирает объект прогнозирования.
3. Пользователь задаёт горизонт прогнозирования.
4. При необходимости пользователь выбирает дополнительные доступные параметры.
5. Пользователь запускает прогнозирование.
6. Система проверяет параметры.
7. Система выполняет предварительную обработку данных.
8. Система формирует данные, необходимые модели.
9. Модель рассчитывает прогнозные значения.
10. Система сохраняет результат и параметры запуска.
11. Пользователю отображается сформированный прогноз.

### Альтернативный сценарий

Если данных недостаточно:

1. система прекращает запуск;
2. пользователь получает сообщение о причине;
3. прогноз не сохраняется как успешно сформированный.

Если возникает ошибка выполнения модели:

1. система регистрирует техническую ошибку;
2. пользователю отображается сообщение о невозможности выполнить прогнозирование;
3. ранее сохранённые результаты остаются доступными.

### Результат

Создан и сохранён новый прогноз потребительского спроса.

## 6. UC-04. Анализ результата прогнозирования

### Цель

Оценить сформированный прогноз.

### Предусловия

Существует успешно сформированный прогноз.

### Основной сценарий

1. Система отображает страницу результата.
2. Пользователь просматривает исторические значения спроса.
3. Пользователь просматривает прогнозируемые значения.
4. Пользователь анализирует график.
5. Пользователь просматривает прогноз в табличной форме.
6. При наличии фактических данных пользователь сравнивает их с прогнозом.
7. Пользователь просматривает рассчитанные метрики качества.

### Результат

Пользователь получает информацию, необходимую для интерпретации результата прогнозирования.

## 7. UC-05. Просмотр истории прогнозов

### Цель

Получить доступ к результатам предыдущих запусков.

### Предусловия

В системе существует хотя бы один сохранённый прогноз.

### Основной сценарий

1. Пользователь переходит в историю прогнозов.
2. Система отображает список сохранённых запусков.
3. Для каждого запуска отображается основная информация.
4. Пользователь выбирает необходимый прогноз.
5. Система открывает подробные результаты выбранного запуска.

### Результат

Пользователь получает доступ к ранее сформированному прогнозу.

## 8. UC-06. Сравнение прогноза с фактическими данными

### Цель

Определить качество ранее сформированного прогноза после появления фактических значений.

### Предусловия

- существует сохранённый прогноз;
- для соответствующего периода доступны фактические данные.

### Основной сценарий

1. Пользователь открывает сохранённый прогноз.
2. Система получает доступные фактические значения.
3. Система сопоставляет их с прогнозируемыми значениями.
4. Система рассчитывает предусмотренные метрики качества.
5. Система отображает фактические и прогнозируемые значения.
6. Пользователь анализирует величину отклонений.

### Результат

Для прогноза доступны объективные показатели его качества.

## 9. UC-07. Повторное прогнозирование с изменёнными параметрами

### Цель

Получить новый прогноз при изменении настроек.

### Предусловия

Пользователь располагает набором данных, пригодным для прогнозирования.

### Основной сценарий

1. Пользователь открывает параметры прогнозирования.
2. Пользователь изменяет доступные настройки.
3. Пользователь запускает новый расчёт.
4. Система формирует новый прогноз.
5. Новый запуск сохраняется отдельно от предыдущего.
6. Пользователь анализирует полученный результат.

### Результат

В системе существует отдельный результат прогнозирования с новым набором параметров.
