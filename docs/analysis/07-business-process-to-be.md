# Целевой процесс прогнозирования потребительского спроса TO-BE

## 1. Назначение целевого процесса

Целевой процесс TO-BE описывает порядок выполнения прогнозирования потребительского спроса после внедрения разрабатываемого программного средства.

Основной целью преобразования процесса является снижение доли ручных операций, автоматизация подготовки данных и прогнозирования, обеспечение единообразной оценки качества моделей и предоставление пользователю результатов в форме, пригодной для анализа и принятия решений.

Разрабатываемое программное средство должно выполнять вычислительные и аналитические операции автоматически, при этом окончательное управленческое решение остаётся за пользователем.

## 2. Общая характеристика процесса TO-BE

После внедрения программного средства специалист взаимодействует с системой через пользовательский интерфейс и выполняет преимущественно операции выбора данных, параметров прогнозирования и анализа результатов.

Операции по проверке, предварительной обработке данных, формированию признаков, запуску модели, расчёту прогнозных значений и вычислению показателей качества выполняются программным средством автоматически.

Результаты прогнозирования сохраняются в системе и могут использоваться для последующего сравнения с фактическими значениями.

## 3. Участники процесса

В целевом процессе выделяются следующие участники.

### 3.1. Пользователь системы

Пользователь выполняет следующие действия:

- загружает или выбирает исходные данные;
- выбирает объект прогнозирования;
- задаёт параметры и горизонт прогноза;
- инициирует процесс прогнозирования;
- анализирует полученные результаты;
- просматривает историю прогнозов;
- использует результаты для поддержки принятия решений.

### 3.2. Программное средство прогнозирования

Программное средство выполняет:

- приём и проверку исходных данных;
- предварительную обработку данных;
- формирование признаков;
- подготовку входных последовательностей;
- применение модели прогнозирования;
- расчёт прогнозных значений;
- вычисление метрик качества;
- сохранение результатов;
- визуализацию прогнозов;
- предоставление истории предыдущих запусков.

### 3.3. Источник данных

Источник данных предоставляет историческую информацию о продажах.

В зависимости от способа реализации источником может являться:

- файл CSV;
- электронная таблица;
- база данных;
- внешняя информационная система;
- другой структурированный источник данных.

## 4. Входные данные процесса

На вход программного средства передаются исторические данные о продажах.

В общем случае набор данных может содержать:

- идентификатор товара;
- категорию товара;
- дату наблюдения;
- количество проданных единиц;
- цену;
- сведения о скидках;
- сведения об акциях;
- дополнительные признаки, влияющие на спрос.

Перед использованием данных система должна выполнить их автоматическую проверку и подготовку.

## 5. Описание процесса TO-BE

### Этап 1. Загрузка или выбор данных

Пользователь передаёт системе набор исторических данных либо выбирает ранее загруженный источник.

Система регистрирует полученный набор данных и инициирует процедуру его проверки.

### Этап 2. Автоматическая проверка данных

Программное средство проверяет данные на наличие:

- пропущенных значений;
- некорректных форматов;
- дублирующихся записей;
- ошибочных дат;
- некорректных числовых значений;
- других нарушений структуры данных.

Если обнаружены критические ошибки, система должна уведомить пользователя и указать причины невозможности продолжения обработки.

### Этап 3. Предварительная обработка данных

После успешной проверки система автоматически выполняет подготовку данных.

В зависимости от используемого алгоритма могут выполняться:

- удаление или обработка пропущенных значений;
- сортировка данных по времени;
- агрегирование;
- нормализация или масштабирование;
- преобразование категориальных признаков;
- формирование временных признаков;
- создание последовательностей для модели прогнозирования.

Результатом этапа является набор данных, подготовленный для применения модели.

### Этап 4. Выбор параметров прогнозирования

Пользователь задаёт необходимые параметры прогнозирования.

К ним могут относиться:

- товар или группа товаров;
- период исторических данных;
- горизонт прогнозирования;
- используемая модель;
- дополнительные параметры запуска.

При наличии единственной рабочей модели часть параметров может быть определена системой автоматически.

### Этап 5. Запуск прогнозирования

Пользователь инициирует построение прогноза.

Система передаёт подготовленные данные в модель и выполняет расчёт прогнозируемых значений спроса.

Во время выполнения операции система должна сохранять информацию о запуске, используемых параметрах и версии модели.

### Этап 6. Расчёт показателей качества

Если для рассматриваемого периода доступны фактические значения, система рассчитывает показатели качества прогнозирования.

Для оценки могут использоваться:

- MAE;
- RMSE;
- MAPE;
- дополнительные метрики, выбранные в ходе разработки.

Полученные значения сохраняются вместе с результатом прогнозирования.

### Этап 7. Сохранение результата

После успешного выполнения прогнозирования система сохраняет:

- дату и время запуска;
- использованный набор данных;
- выбранные параметры;
- версию модели;
- прогнозируемые значения;
- фактические значения при их наличии;
- рассчитанные показатели качества.

Это обеспечивает возможность последующего анализа и воспроизводимости результата.

### Этап 8. Визуализация прогноза

Система отображает результат пользователю в удобной форме.

Результат может включать:

- график исторических значений;
- график прогнозируемого спроса;
- таблицу прогнозных значений;
- показатели качества;
- основные параметры запуска.

При наличии фактических данных должна поддерживаться возможность визуального сравнения прогноза с реальными значениями.

### Этап 9. Анализ результата пользователем

Пользователь анализирует сформированный прогноз и показатели качества.

При необходимости пользователь может изменить параметры прогнозирования и повторно запустить процесс.

### Этап 10. Использование результата

Результаты прогнозирования используются как информационная поддержка при планировании будущего спроса.

Программное средство не должно автоматически принимать управленческие решения, связанные с закупками, запасами или другими бизнес-процессами.

## 6. Автоматизируемые операции

В целевом процессе программное средство должно автоматизировать следующие операции:

- проверку структуры и качества входных данных;
- предварительную обработку данных;
- формирование признаков;
- подготовку входных данных для модели;
- построение прогноза;
- расчёт показателей качества;
- сохранение результатов;
- формирование визуального представления;
- ведение истории прогнозов.

Пользователь должен преимущественно выполнять операции выбора, запуска и интерпретации результата.

## 7. Обработка ошибок

Целевой процесс должен учитывать возможные ошибки на отдельных этапах.

Система должна информировать пользователя в случаях:

- невозможности чтения входного файла;
- некорректной структуры данных;
- отсутствия обязательных полей;
- недостаточного объёма исторических данных;
- ошибки предварительной обработки;
- невозможности выполнения модели;
- отсутствия сохранённой модели;
- внутренних ошибок выполнения прогнозирования.

Сообщение об ошибке должно быть понятным пользователю и по возможности содержать описание причины и рекомендации по её устранению.

## 8. Ожидаемые улучшения процесса

Переход от AS-IS к TO-BE должен обеспечить:

- сокращение количества ручных операций;
- уменьшение трудоёмкости подготовки данных;
- снижение вероятности ошибок при выполнении расчётов;
- воспроизводимость прогнозирования;
- централизованное хранение результатов;
- единый подход к оценке качества моделей;
- возможность быстрого повторного запуска прогнозирования;
- повышение удобства анализа результатов;
- возможность работы с большим количеством исторических данных.

## 9. Результат целевого процесса

Результатом выполнения процесса TO-BE является сформированный и сохранённый прогноз потребительского спроса с указанием параметров запуска, версии используемой модели и показателей качества.

Пользователь получает возможность анализировать прогнозные значения, сравнивать их с историческими и фактическими данными и использовать результат в качестве информационной поддержки при принятии решений.

Сформированный процесс TO-BE определяет основные взаимодействия между пользователем и программным средством и является основой для дальнейшего определения функциональных требований и проектирования архитектуры системы.
